# Сборка собственных dub-паков (пайплайн)

Как из «видео + .srt с ролями» собрать пак для Dub Choice. Совместимость с
The Choicer Voicer **не требуется** — используем современные кодеки, но
конвенции формата (имена файлов, ключи ini) соблюдаем.

Исходники паков лежат в `../dc_dubpacks/<pack>/` (вне git). Первый пак —
`hp_owl` (Гарри Поттер, «Я вам не сова!»).

## TL;DR: собрать новый пак

Положить в `../dc_dubpacks/<pack>/` видео и `.srt` с ролями, дальше:

```bash
PACK=hp_owl; SRC="исходник.mov"; DUR=72.87    # DUR — длительность видео, с
cd ../dc_dubpacks/$PACK && mkdir -p work build
S=../../app/scripts/dubpack; PY=../.venv/bin/python; V=work/sep/htdemucs/original

# 1. аудио и видео из исходника
ffmpeg -y -i "$SRC" -vn -ac 2 -ar 44100 -c:a pcm_s16le work/original.wav
ffmpeg -y -i "$SRC" -an -vf scale=-2:540 -c:v libx264 -profile:v high \
  -pix_fmt yuv420p -crf 28 -preset slow -force_key_frames "expr:gte(t,n_forced*2)" \
  -movflags +faststart build/dub_video.mp4

# 2. разделение голоса и фона (при первом запуске тянет модель ~87 МБ)
$PY -m demucs --two-stems=vocals -n htdemucs -d mps -o work/sep work/original.wav

# 3. тайминги слов
ffmpeg -y -i work/original.wav -ac 1 -ar 16000 -c:a pcm_s16le work/orig16k.wav
whisper-cli -m ../models/ggml-large-v3-turbo.bin -l ru -ml 1 -sow -oj \
  -of work/w_orig -f work/orig16k.wav

# 4. ✋ РУКАМИ: написать clips.json (формат ниже) — единственный шаг с головой

# 5. выравнивание, уточнение, проверка
python3 $S/align.py work/w_orig.json clips.json work/aligned.json --duration=$DUR
$PY $S/refine_onsets.py $V/vocals.wav work/aligned.json work/aligned2.json   # без --apply: посмотреть
$PY $S/refine_onsets.py $V/vocals.wav work/aligned.json work/aligned2.json --apply
$PY $S/check_bounds.py $V/vocals.wav work/aligned2.json

# 6. сейф-зона — раздвигаем клипы, чтобы было время записать дубль
python3 $S/safe_zone.py work/aligned2.json work/safezoned.json --duration=$DUR

# 7. бэкинг и сборка (бэкинг — от aligned2.json, он не зависит от сейф-зоны)
$PY $S/build_backing.py work/original.wav $V/no_vocals.wav $V/vocals.wav work/aligned2.json work/backing.wav
python3 $S/build_pack.py work/safezoned.json work/original.wav work/backing.wav \
  build/dub_video.mp4 build --icon-at=45
ffmpeg -y -i work/original.wav -c:a libmp3lame -b:a 128k -ac 2 build/_original_track.mp3
(cd build && zip -q -X -r ../$PACK.zip . -x '.*')

# 8. проверка парсером (скрипт обходит ПОДпапки указанного пути)
cd ../../app && npm run test:packs -- "../dc_dubpacks/$PACK"
```

`align.py` и `build_pack.py` идут на системном `python3`, остальным нужен
venv (в них numpy).

## Формат `clips.json` — то, что пишется руками

Единственный вход, который не выводится автоматически: авторская нарезка.

```jsonc
{
  "title": "Гарри Поттер — Я вам не сова!",   // название пака
  "subtitle": "Harry Potter and the Goblet of Fire",
  "authors": ["barinboim"],
  "clips": [
    {
      "n": 1,                     // номер по порядку = префикс имени файла
      "name": "nevill",           // ЛАТИНИЦЕЙ: файл станет 01_nevill.mp3/.ini
      "character": "Невилл",      // как показывается игроку, кириллица можно
      "text": "Потрясающе!",      // caption; он же выравнивается по словам whisper
      "srt": 1,                   // номер строки SRT, откуда взят текст (null — если ниоткуда)
      "hint": [3.5, 4.9],         // окно поиска; страховка от артефактов whisper
      "lock_start": 48.86,        // необязательно: жёстко заданная граница,
      "lock_end": 50.93           // её не тронут ни выравнивание, ни уточнение
    }
  ]
}
```

- `hint` — приблизительное окно. Для клипов, взятых прямо из строки SRT,
  берётся её тайминг; для кусков внутри длинной строки — прикидывается
- `lock_start` / `lock_end` нужны в двух случаях: владелец назвал границу на
  слух, либо реплики нет в выводе whisper (невербальный звук — см. 4б)
- Клипы должны идти по возрастанию времени: `refine_onsets.py` смотрит на
  соседей по списку, чтобы не заехать на чужую реплику

## Решения, уже принятые (2026-08-12)

| Вопрос | Решение |
|---|---|
| ASR | `whisper.cpp` CLI (brew) + ggml-large-v3-turbo. MacWhisper — GUI-only, из скрипта не вызывается |
| Разделение голоса и фона | Demucs `htdemucs --two-stems=vocals`; запасной вариант — `audio-separator` с MelBand Roformer |
| `_backing_track` | **Гибрид**: вне речи — оригинальная дорожка, внутри речевых интервалов — `no_vocals`, кроссфейд 150 мс. Собираем и чистый `no_vocals` для A/B |
| Где «внутри речи» | **VAD по стему `vocals`**, а не слова whisper — см. раздел ниже, это ошибка, на которой пак пришлось пересобирать |
| Дробление реплик | По смене говорящего (обязательно) → по предложению → по клаузе, если >7 с. Соседние короткие предложения одного говорящего слипаются, пока клип < ~4 с |
| Окно записи (сейф-зона) | Границы из `align.py`/`refine_onsets.py` — впритык к речи, для бэкинга это правильно, но окно записи в игре = ровно длине клипа (`recorder.start(buf.duration, …)` в `main.ts`). `safe_zone.py` раздвигает клип на PRE_ROLL/POST_ROLL и тянет короткие клипы до MIN_DURATION, не залезая в речь соседа — см. раздел ниже |
| Видео | H.264 High, **1304×540**, **CRF 28**, `yuv420p`, `+faststart`, **без аудиодорожки** (движок всегда держит видео muted). CRF 23 давал 14.2 МБ, 26 → 9.9, 28 → 7.7; на мягкой тёмной картинке 28 визуально неотличим от 23. **Ключевой кадр не реже раза в 2 с** (`-force_key_frames "expr:gte(t,n_forced*2)"`) — без этого libx264 сам расставляет их по сцен-катам и на статичных участках даёт разрывы до 10 с; перемотка на реплику посреди такого разрыва требует декодировать секунды видео назад и на слабом декодере/сети даёт чёрный экран, пока кадр не досчитается (поймано на паке `gofman`, где после 25-й секунды разрывы были ровно 10 с) |
| Аудио пака | **MP3** — в локальном ffmpeg нет libvorbis, а Opus-in-Ogg ненадёжен в Safari |
| JPEG-кадры реплик | **Делаем** (с 2026-08-12): `NN_<name>.jpg`, высота 480, `-q:v 4`, кадр из середины РЕЧИ (`content_start`/`content_end`), плюс `image=` в ini. Нужны экрану результатов, где кадр стоит рядом с баллом; ~25 КБ на реплику, на 63-клиповый пак ~0.9 МБ. Раньше не делали — см. раздел в конце |

## Пайплайн

### 0. Окружение (один раз)

- `brew install whisper-cpp`, модель `ggml-large-v3-turbo.bin` (1.62 ГБ) с
  HuggingFace — оттуда качается быстро, в отличие от GitHub
- venv на **python3.12** (не 3.14 — torch его не поддерживает):
  `python3.12 -m venv .venv`
- **`pip install demucs` напрямую зависает** на разрешении зависимостей
  (резолвер перебирает версии torch, кэш при этом не растёт — процесс жив, но
  бесполезен). Рабочий путь: скачать колёса `torch` и `torchaudio`
  **одинаковой версии** (2.11.0) через curl с files.pythonhosted.org,
  поставить локально, и только потом `pip install demucs`
- files.pythonhosted.org из этой сети отдаёт 60–260 КБ/с: torch (76 МБ)
  качается 5–20 минут. Колёса складываем в `dc_dubpacks/wheels/`, чтобы не
  качать повторно
- **numpy ставится отдельно**: demucs 4.1.0 его в зависимостях не тянет, а
  без него падают и он сам, и наши скрипты (`pip install numpy`)
- Машина: M2 / 8 ГБ. Demucs на 73 с укладывается в пару минут; при нехватке
  памяти — `--segment 10`. Ключ `-d mps` обязателен, иначе считает на CPU
- Всё лежит рядом с паками, вне git: venv в `dc_dubpacks/.venv`, модель
  whisper в `dc_dubpacks/models/`, скачанные колёса в `dc_dubpacks/wheels/`

### 1. Извлечение аудио

`ffmpeg -i source.mov -vn -ac 2 -ar 44100 -c:a pcm_s16le original.wav`

Работаем везде с WAV 44.1/16 (или float32) и сжимаем только на финальном шаге.

### 2. Разделение

`python -m demucs --two-stems=vocals -n htdemucs -d mps -o work/sep work/original.wav`

Стемы окажутся в `work/sep/htdemucs/<имя файла без расширения>/` —
`vocals.wav` и `no_vocals.wav`, 16 бит стерео 44.1, той же длины что вход.

Проверка: в `no_vocals` не должно оставаться разборчивых слов — в финальном
монтаже они наложатся на дубль игрока и это сразу слышно. Если остаточный
голос есть — переходим на `audio-separator` с MelBand Roformer.

### 3. Транскрипция с word-level таймингами

Аудио для whisper — моно 16 кГц:
`ffmpeg -i original.wav -ac 1 -ar 16000 -c:a pcm_s16le orig16k.wav`

`whisper-cli -m ggml-large-v3-turbo.bin -l ru -ml 1 -sow -oj -of w -f orig16k.wav`

`-ml 1 -sow` = один сегмент на слово. Это **не** источник текста — текст
берём из SRT (там роли и правильная пунктуация). Whisper нужен **только для
таймингов**.

Грабли whisper.cpp:

- **`-dtw` бесполезен**: DTW-тайминги в JSON не попадают, вывод байт в байт
  совпадает с прогоном без него. Не тратить время
- **Слова с нулевой длительностью**: whisper вешает все слова начала сегмента
  на одну метку (`start == end`), а длительность всего блока прячет в
  последнем слове — таких было 26 из 99. `align.py` чинит это, раздавая
  интервал пропорционально длине слов в символах
- **Первое слово ролика получает `start = 0.00`** (артефакт ведущей тишины).
  Лечится подсказкой из SRT: если граница ушла больше чем на 0.5 с за окно
  субтитра, берём тайминг субтитра

### 4. Резка на клипы

Правила по порядку:

1. Смена говорящего внутри строки SRT → обязательный разрез
2. Границы предложений (`.`, `!`, `?`, `…`)
3. Если предложение всё равно > ~7 с — режем по клаузе на запятой, выбирая
   разрез в самой длинной паузе между словами
4. Обратная склейка: соседние куски одного говорящего сливаются, пока
   суммарная длительность < ~4 с
5. Границы клипа = начало первого слова − 80 мс, конец последнего + 150 мс
6. `refine_onsets.py` уточняет границы по энергии стема `vocals` — там нет
   музыки, поэтому порог срабатывает ровно на начале голоса

Про пункт 6 стоит знать, обе грабли выловлены на этом паке:

- Граница обязана расширяться **только по непрерывному куску речи** и никогда
  не перепрыгивать паузу. Первая версия искала «последний звук в окне ±0.6 с»
  и хватала то возглас через полсекунды тишины, то голос соседней реплики
- Сдвиг наружу ограничен половиной зазора до соседа, внутрь — свободно до
  0.6 с. Асимметрия отражает реальный перекос whisper: он начинает сегмент
  раньше слова, а не позже

### 4а-2. Грабли `refine_onsets.py`: короткая реплика без паузы до соседа

Если между двумя репликами одного или разных говорящих нет реальной паузы
(слитная скороговорка — например короткое «What?» перед «Well, did you?»),
`refine_onsets.py` может выдать для короткого клипа **конец раньше начала**
(например `11.32–11.18`): он ищет границу речи независимо для каждого
клипа, а без паузы между ними это один сплошной кусок энергии, в котором
нет чистой границы для короткого клипа посередине. Симптом виден прямо в
таблице предпросмотра (`было/стало`) — стоит проверять её глазами, а не
сразу жать `--apply`.

Лечится вручную: взять `start`/`end` из **до-`refine` таблицы** (вывод
`align.py`, там граница берётся по слову whisper и обычно вменяема) и
прописать их как `lock_start`/`lock_end` в `clips.json` для этого клипа —
`refine_onsets.py` уважает лок и не трогает такую границу. Найдено и
исправлено на паке `theroom_ididnot` (клип «What?» между «I have a problem…»
и «Well, did you?»).

### 4а. Проверка границ (обязательно)

`check_bounds.py` слушает стем `vocals` прямо снаружи каждой границы: если
там речь — границу поставили посреди слова. Соседние реплики впритык дают
ложные срабатывания, поэтому флаг засчитывается только если до соседа больше
0.15 с. Именно эта проверка поймала обрезанный хвост клипа 15. Возвращает
код 1 при находках — годится для CI.

Спорные места показываются текстом с таймингами — владелец слушает и говорит,
на какой секунде бить.

### 4б. Речевая маска для бэкинга — только по стему

**Самая дорогая ошибка этого пака.** Первая версия брала интервалы речи из
слов whisper. Whisper не транскрибирует невербальное — вздохи, смешки,
мычание. Мычание Гермионы на 48.9–50.8 в его вывод не попало, гибрид счёл
этот участок паузой, взял туда **оригинальную** дорожку и оставил её голос
в фоне. В игре это слышно сразу: поверх дубля игрока звучит оригинал.

Поэтому маску считает `vad.py` по энергии стема `vocals` — стем знает про
голос всё, независимо от того, распознались ли слова. Интервалы из whisper
подмешиваются сверху как страховка, но ведущий источник — стем.

Мораль для будущих паков: **всё, что решает «где голос», должно смотреть в
стем, а не в текст.**

### 4в. Сейф-зона окна записи

Границы после `align.py`/`refine_onsets.py` выверены впритык к голосу — это
верно для бэкинга (речевая маска должна быть точной), но **окно записи в
игре равно ровно длине аудиофайла клипа**: `recorder.start(buf.duration, …)`
в `main.ts` — движок не даёт игроку времени сверх длины `NN_name.mp3`. На
паке «Зелёный слоник» первая сборка резала клипы впритык (align+refine), и
короткие реплики вроде «А?» (0.3 с) или «Тигр!» (0.65 с) физически не
оставляли времени сказать свою фразу — источник этого правила.

`safe_zone.py` раздвигает каждый клип независимо от бэкинга (бэкинг уже
собран по полю `speech` из `aligned2.json`, которое от границ клипов не
зависит):

- `PRE_ROLL` (0.35 с) и `POST_ROLL` (0.55 с) добавляются к границам речи;
  хвост больше головы — игроки чаще договаривают с запозданием, чем
  начинают заранее
- Если после этого клип короче `MIN_DURATION` (2.2 с), дефицит добирается
  ещё, 35% вперёд / 65% назад
- **Заходить в реплику соседа — нормально, но в меру.** Игрок дублирует
  только свою реплику, а движок и так проигрывает перекрывающиеся `cue`
  независимо друг от друга (`composer.ts` — каждая запись это свой
  `AudioBufferSourceNode` на своём таймстампе); так же вели себя
  оригинальные дав-паки на плотной речи. Но щедрый `PRE_ROLL`/`POST_ROLL`/
  добивка до `MIN_DURATION` работают только в свободном пространстве —
  как только граница пересекает СОБСТВЕННУЮ речь соседа, вход в неё режется
  до `NEIGHBOR_BITE` (0.2 с, «си-» от «сиди») независимо от того, откуда
  взялось желание раздвинуться шире. Короткий клип между двумя тесными
  соседями может остаться короче `MIN_DURATION` — это ожидаемо и лучше,
  чем проглотить всю реплику соседа целиком (как было в первой версии
  правила: «Чего вы?» перед «Молчать, блядь!» вместо кусочка забрал 0.98 с
  из 1.17-секундного соседа — почти весь его целиком)
- Единственная жёсткая граница помимо этого — собственное содержимое клипа
  (никогда не резать свою же речь) и края видео (0 и общая длительность)

На «Зелёном слонике» 58 из 63 клипов дотянули до 2.2 с; у 5 не получилось —
там клип зажат между двумя соседями (например #13 «А?» между двумя
репликами Начальника), и `NEIGHBOR_BITE` с обеих сторон в сумме короче
цели. Это ожидаемое поведение, не баг.

Скрипт пишет в `start`/`end` уже раздвинутые границы, а исходные (для
справки) сохраняет как `content_start`/`content_end`. **`build_pack.py`
берёт файл после `safe_zone.py`, а не после `refine_onsets.py`** —
`_backing_track` при этом собирается из `aligned2.json` отдельным шагом.

### 5. Сборка файлов пака

```
dub_video.mp4            # H.264 1304×540 CRF 28, без звука
_backing_track.mp3       # гибридный фон, 192 kbps stereo, полная длина видео
_original_track.mp3      # полная сцена С голосами, 128 kbps stereo — для закадра:
                         #   ffmpeg -i work/original.wav -c:a libmp3lame -b:a 128k \
                         #     -ac 2 build/_original_track.mp3
_pack_info.ini           # [data] title, subtitle, icon, authors, lang
icon.png                 # кадр из видео, 512×512 (кроп по центру)
NN_<latin>.mp3           # оригинал реплики (полный микс), 128 kbps
NN_<latin>.ini           # [data] caption, caption_<lang>, dub_timestamps, dub_characters, image
NN_<latin>.jpg           # кадр-превью реплики, высота 480 (для экрана результатов)
```

- **Имена файлов — латиницей** (`01_nevill`, `02_garry`, `03_germiona`,
  `04_ron`, `05_babka`): кириллица в именах внутри ZIP ломается на разных
  распаковщиках. Кириллица допустима только *внутри* ini (UTF-8)
- `dub_timestamps=[<начало клипа в видео>]` — по нему движок и ставит запись
  игрока в финальном монтаже, и перематывает видео на превью реплики
- Аудио реплики — **оригинальный микс**, не стем: игрок должен слышать сцену
  как она есть. Если серая волна окажется нечитаемой из-за музыки —
  переключимся на `vocals`
- `build_pack.py` **всегда перезаписывает** `icon.png` кадром на `--icon-at`.
  Если нужна конкретная картинка (не автовырез), накладывать её поверх
  `build/icon.png` **после** `build_pack.py`, вручную кропнув в квадрат
  512×512: `ffmpeg -i картинка.jpg -vf "crop=ih:ih,scale=512:512" build/icon.png`

### 5а. Режим переводчика: субтитры на втором языке

Пак может нести субтитры на нескольких языках — тогда игрок переключает
язык прямо над текстом реплики и озвучивает перевод. Это наше расширение
формата: оригинальная игра незнакомые ключи молча игнорирует, так что пак
остаётся совместимым и с ней, и со старыми версиями Dub Choice.

```ini
; _pack_info.ini — язык оригинальных субтитров
[data]
title="Lotr - Bridge of Khazad Dum"
lang="en"

; NN_<latin>.ini — перевод рядом с оригиналом
[data]
caption="“You shall not pass!”"
caption_ru="Ты не пройдёшь!"
dub_timestamps=[33.352]
```

- Ключ перевода — `caption_<код языка>`: `caption_ru`, `caption_de`,
  `caption_pt-br`. Регистр не важен, код приводится к нижнему
- **Дорожка дубляжа** (наше расширение): `_voices_<код>.mp3` — только голос,
  вся сцена одним файлом, плюс `audio_langs=["ru"]` в `_pack_info.ini`.
  Реплики из неё игра режет сама по `dub_timestamps`, отдельными файлами их
  возить не надо. Фон общий с оригиналом: музыка в дубляже та же.

  Этим пайплайном дорожка не делается — её собирает студия (импорт файла,
  синхронизация кросс-корреляцией, demucs, whisper для субтитров этого
  языка). Руками путь такой же: выровнять дубляж по таймлайну оригинала
  (сдвиг, а при разной скорости — ресемпл), прогнать demucs, вокал сжать в
  mp3 128k и положить как `_voices_<код>.mp3`
- **Код не обязан быть кодом ISO.** В кино говорят и на выдуманных языках,
  поэтому годится любое слово латиницей до 16 символов: `caption_lesnoy`,
  `caption_elvish`. Такому языку дайте название прямо в паке, иначе на
  пилле будет код заглавными:
  ```ini
  langname_lesnoy_ru="Лесной"
  langname_lesnoy_en="Forest"
  ```
  Названия из пака важнее словаря игры — только автор знает, как подписать
  свой язык. Студия пишет эти ключи сама, когда язык заводится словом
- `lang` в `_pack_info.ini` говорит, на каком языке сам `caption`. Без него
  пилл оригинала подпишется нейтральным «Оригинал», всё остальное работает
- Сессия стартует на языке интерфейса, если пак его несёт (русский UI +
  `caption_ru` → сразу русские субтитры), иначе на языке оригинала
- Переводить **каждую** реплику не обязательно: где `caption_ru` нет, при
  переключении показывается оригинал. Пустая строка языком не считается
- Языки берутся из реплик, а не из `_pack_info.ini`: пак попадает в режим
  переводчика ровно тогда, когда хоть одна реплика несёт перевод
- Реплики-звуки (смех, крик, шипение) переводить незачем — оставляй как есть
- Отдельного тега в галерее у таких паков нет: языки перечислены в строке
  характеристик на карточке пака
- Игрок может переписать текст любой реплики под себя прямо в игре, но эта
  правка живёт только в текущей сессии и в пак не возвращается

### 5б. Закадровый режим: `_original_track`

В финале игрок выбирает, заменить голоса персонажей своими («Дубляж») или
положить озвучку поверх приглушённого оригинала («Закадр»). Закадру нужна
полная дорожка сцены **с голосами** — её и кладём в пак:

```bash
ffmpeg -i work/original.wav -c:a libmp3lame -b:a 128k -ac 2 build/_original_track.mp3
```

- Файл опциональный, но для своих паков делаем всегда: +0,8…5,5 МБ к архиву
- Без него закадр собирается из `_backing_track` и кусков-реплик, а они
  несут собственный фон — под репликами он выходит примерно на 2 дБ плотнее.
  Для чужих паков только так, исходников у нас нет
- Слайдер «громкость оригинала» на премьере ведёт всю эту дорожку целиком,
  вместе с музыкой и шумами — как в настоящем закадровом переводе

## Скрипты (`scripts/dubpack/`)

| Скрипт | Что делает |
|---|---|
| `align.py` | Текст клипов из `clips.json` + слова whisper → `aligned.json` с таймингами. Чинит нулевые длительности, страхуется подсказками SRT |
| `refine_onsets.py` | Уточняет границы по энергии стема `vocals`. Без `--apply` — только показывает таблицу сдвигов |
| `check_bounds.py` | Проверяет, что ни одна реплика не обрезана по краю. Код 1 при находках |
| `vad.py` | Общий поиск речи по энергии стема: `envelope`, `threshold`, `voiced_regions` |
| `safe_zone.py` | Раздвигает клипы под окно записи (PRE_ROLL/POST_ROLL/MIN_DURATION); в речь соседа заходить можно, но не больше NEIGHBOR_BITE — см. «4в. Сейф-зона окна записи» |
| `build_backing.py` | Гибридный `_backing_track` (или `--pure` для чистого стема). Принимает **и** `no_vocals`, **и** `vocals` — второй нужен для VAD |
| `build_pack.py` | Режет клипы и кадры-превью, пишет все `ini`, иконку, `_backing_track.mp3`. На вход — файл после `safe_zone.py`, не после `refine_onsets.py` |
| `make_frames.py` | Кадры-превью (`NN_*.jpg` + `image=`) для уже собранного пака — тем же кодом, что и `build_pack.py` |

Входной `clips.json` (авторская нарезка: роль + текст + окно из SRT) пока
пишется руками — это единственный шаг, где нужна голова. Дальняя цель из
`CLAUDE.md` — редактор паков в самом приложении; этот пайплайн его прототип.

## Пак из одних криков: «Звёздные войны — Ты был Избранным!» (2026-08-13)

`dc_dubpacks/chosen_one`, 29 клипов, из них **19 невербальных** (крики,
рыки, стоны). Собран локально, в галерею не публиковался. Случай, ради
которого стоит перечитать раздел «4б»: whisper не дал вообще ничего на
2/3 хронометража, и **весь пак нарезан по стему `vocals`**, а не по тексту.

- **Границы криков задаются `lock_start`/`lock_end` из стема.** Порядок
  такой: прогнать `vad.voiced_regions` по `vocals.wav`, взять регионы,
  добавить паддинг −0.06/+0.12 и записать локами в `clips.json`. Whisper
  здесь бесполезен, `align.py` для таких клипов работает как транспорт
  локов, а `refine_onsets.py` их не трогает
- **Смычка `gap_bridge` управляет дроблением крика.** Сплошной блок
  14.98–18.69 при штатных 0.12 с — один клип на 3.7 с; при 0.04 с он
  распадается на два настоящих крика (14.98–16.65 и 16.73–18.69). Если
  крик кажется подозрительно длинным, пересканировать с меньшей смычкой
- **Тайминги SRT на невербальном врут на 0.5–1 с** (их пишут на слух).
  Здесь SRT-строки на крики разошлись со стемом настолько, что `hint`
  пришлось брать из стема, а не из субтитра
- **«Голос это или шум?» — спектральная проверка.** В стем `vocals`
  протекают лава и световые мечи, и на слабых всплесках вне SRT глазами по
  огибающей их не отличить от стонов. Различает отношение энергии
  80–1000 Гц к 4–8 кГц плюс автокорреляционный пик на F0 70–400 Гц:
  у голоса низ/верх +11…+39 дБ при гармоничности 0.4–0.9, у шума меча на
  27.2 с было **−6.3 дБ и 0.20** — единственный кандидат, выброшенный из
  пака. Скрипт разовый, лежал в scratchpad; при следующем таком паке
  проще написать заново, чем искать
- **`check_bounds.py` на криках срабатывает по делу.** Оба флага (клипы 6
  и 29) оказались реальным затуханием на краю: VAD-порог отрезал атаку
  стона и хвост финального крика. Лечится не отключением проверки, а
  печатью огибающей по кадрам 10 мс вокруг границы и правкой лока
- **Подавление голоса −2.7 дБ здесь НЕ означает брака.** Сцена плотная
  (оркестр + лава), голос всего на 6.9 дБ ниже микса, поэтому его удаление
  почти не меняет суммарный уровень — против −18.3 дБ на тихом `hp_owl`.
  Показатель, который реально проверяет гибрид, — «бэкинг против
  `no_vocals` внутри речи»: должен быть 0.0 дБ
- Сейф-зона: 28 из 29 клипов дотянуты до 2.2 с, заходы в соседей по 0.2 с
  здесь безобидны — соседи тоже крики, «начало слова» откусывать нечего

## Публикация пака в галерею сайта

**Паки живут в Cloudflare R2, не в репозитории** (с 2026-08-17). Список
галереи тоже не в коде: страница качает `manifest.json` из того же бакета
при каждом заходе. Поэтому публикация пака **не требует ни пересборки, ни
пуша сайта** — достаточно залить файлы и обновить манифест.

Раньше было иначе: паки лежали в `public/packs/`, качались с
`raw.githubusercontent.com` и резались на части по 4 МБ (лимит GitHub —
100 МБ на файл, плюс пуш рвался на объёме). Ничего этого больше нет — zip
заливается цельным.

1. Добавить пак в константу `PACKS` в `scripts/dubpack/build_manifest.py`:

```python
("shrekfiona", "Shrek — Fiona and Bird",
 "studio/projects/shrek_fiona_and_bird/shrek_fiona_and_bird.zip",
 ["мультфильм", "шрек"], None, None),
#  id, заголовок, путь к zip, ручные теги, дата, иконка
```

2. Собрать манифест и залить всё в R2:

```bash
cd app
python3 scripts/dubpack/fetch_plays.py > build/plays.json   # статистика с VPS
python3 scripts/dubpack/build_manifest.py --plays build/plays.json --upload
```

Скрипт сам прочитает архив (реплики, персонажей, длительность через ffprobe,
языки), достанет иконку, проставит теги, зальёт zip + иконку и **последним**
обновит `manifest.json` — пока он не обновлён, сайт о новом паке не знает.

- **`id` должен быть уникальным** — в списке уже есть `harrypotter` (другой
  пак по тем же фильмам), так что новый назван `hpowl`
- `sizeBytes` считается автоматически, вручную его больше вводить не нужно
- Иконка ищется в `public/pack-icons/<id>.png`, затем в самом архиве
  (`icon=` из `_pack_info.ini`), затем берётся первый кадр реплики. Рисуется
  с `object-fit: cover`, поэтому пропорция иконки не важна
- **Дата берётся из пака**: `built="YYYY-MM-DD"` в `_pack_info.ini` пишет
  `build_pack.py` (и студия, она вызывает его же). В конфиге можно оставить
  `None`. По этой дате строится полка «Новинки»
- Проверять прод после заливки не обязательно ждать деплой — манифест
  подхватывается сразу, кэш на нём 60 секунд

### Теги галереи

Теги приезжают в манифесте полем `tags`. Часть проставляется руками в
`PACKS` (жанр, франшиза, `18+`), часть выводится из самого пака:

| Тег               | Откуда берётся                                    |
|-------------------|---------------------------------------------------|
| `русская озвучка` | `lang="ru"` либо дорожка `_voices_ru` в архиве     |
| `короткий ролик`  | суммарная длина реплик ≤ 60 с                      |
| `монолог`         | в паке ровно один персонаж                         |

- Автовывод «русской озвучки» не срабатывает на старых фанатских паках
  (`hpowl`, `slonik`) — у них в `_pack_info.ini` нет поля `lang` вовсе,
  поэтому тег проставлен им руками
- **`18+` намеренно не фильтр**, а пометка: бейдж на обложке в полке и
  красная подпись в строке карточки. Фильтровать каталог по возрастному
  цензу смысла нет, а предупредить нужно. Он исключён из пиллов через
  `HIDDEN_TAGS` в `main.ts`
- Тултип есть только у `18+` (`tagAdultTooltip` в `i18n.ts`, ru/en)
- Подписи тегов для английского интерфейса — словарь `TAG_EN` в `i18n.ts`;
  незнакомый тег показывается как есть, так что манифест может принести
  любой новый тег без правок кода
- Сам факт публикации пака с пометкой 18+ (плотная ненормативная лексика,
  не порнографический/жестокий контент) — решение владельца сайта, не
  проверяется автоматически ничем

## Кадр-заставка вместо превью-картинки (сделано)

Раньше при отсутствии `image` экран реплики показывал плейсхолдер
`dub-noimage`. Теперь `hideWatchVideo()` в `main.ts` не прячет слот с
плеером, а оставляет видео **на паузе в `dub_timestamps[0]`**.

Работает только для `videoKind === "native"` (mp4/webm): у ogv.js отрисовка
кадра после перемотки на паузе ненадёжна, там остаётся старое поведение.
Такие паки почти всегда идут со своими картинками, так что потери нет.

## JPEG-кадры реплик (сделано 2026-08-12)

Заставки на паузе хватало экрану реплики, но не экрану результатов: там
кадры всех реплик стоят списком одновременно, а перематывать ради каждого
видео в браузере дорого (и у ogv.js ненадёжно). Поэтому кадры режем заранее.

- `build_pack.py` делает их сам (отключается `--no-frames`), момент кадра —
  середина **речи** клипа: по краям сейф-зона, там персонаж может быть ещё
  не в кадре или уже вне его
- `make_frames.py <pack_dir> [--spec=work/safezoned.json]` — то же самое для
  **уже собранного** пака: читает `NN_*.ini`, режет кадры, дописывает
  `image=`. Идемпотентен (`image=` не дублируется). Без `--spec` середина
  берётся по длительности аудиофайла клипа
- Настройки по умолчанию: высота 480 (`--height`), `-q:v 4` (`--quality`),
  доля интервала 0.5 (`--at`). Это ~15–45 КБ на кадр
- Кадры добавлены задним числом всем нашим пакам: `hp_owl` 10.8 → 11.5 МБ,
  `slonik_pearharbor` 26.6 → 27.5 МБ, `theroom_ididnot` 4.3 → 4.6 МБ.
  (Раньше после пересборки надо было руками править `sizeBytes` — теперь
  его считает `build_manifest.py`)
- Экран реплики показывает картинку **вместо** видео на паузе (приоритет
  `image` не менялся). Разница 480p против 540p видео на глаз незаметна
